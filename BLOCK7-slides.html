Cấu hình PostgreSQL

Migration npm run db:search và câu SQL thật

-- api/prisma/search.sql (chạy lại sau mỗi db:push)
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;

-- index biểu thức: phải trùng y hệt câu truy vấn
CREATE INDEX IF NOT EXISTS dishes_fts_idx
  ON dishes USING GIN (to_tsvector('simple',
    name || ' ' || coalesce(description, '')));

CREATE INDEX IF NOT EXISTS dishes_name_trgm_idx
  ON dishes USING GIN (name gin_trgm_ops);
  • simple cho cả document và query; coalesce vì mô tả có thể NULL.
  • Ngưỡng gần đúng 0.3 (word_similarity).
-- fulltext: /api/dishes?mode=fulltext&q=phở bò
SELECT id FROM dishes
WHERE to_tsvector('simple', name || ' ' ||
        coalesce(description, ''))
      @@ plainto_tsquery('simple', $1)
ORDER BY ts_rank(…) DESC, id ASC
LIMIT $3 OFFSET $4

-- fuzzy: /api/dishes?mode=fuzzy&q=bun
SELECT id FROM dishes
WHERE word_similarity(unaccent($1),
        unaccent(name)) >= $2   -- 0.3
ORDER BY word_similarity(…) DESC, id ASC
LIMIT $4 OFFSET $5

Câu đếm total dùng cùng đoạn WHERE. Log thật bằng LOG_SQL=1.

Đây là SQL thật ghi được từ terminal API khi bật LOG_SQL=1. Vì Prisma không mô tả được index biểu thức nên dùng file SQL riêng.

Câu 4 · Lỗi phát hiện #1

Gõ % hoặc _ trả về toàn bộ thực đơn

Nguyên nhân

Prisma contains sinh name ILIKE '%' || q || '%' nhưng không escape ký tự đại diện của LIKE: q=% → mẫu %%% khớp mọi tên. Đúng tình huống slide 25 cảnh báo.

Tái hiện

curl "/api/dishes?q=%25&page=1&pageSize=1"
# kỳ vọng total = 0 · thực tế total = 51 (cả seed cũ)

Sửa — escapeLike()

text.replace(/[\\%_]/g, "\\$&")   // 100% → 100\%

Trước khi sửa commit 407ae17

PASS dishes: tổng số món
FAIL dishes: q=% là ký tự thường
     — total = 51, bằng toàn bộ 51 món
FAIL dishes: q=_ là ký tự thường
     — total = 51, bằng toàn bộ 51 món

Sau khi sửa commit 83f981e

PASS dishes: q=% là ký tự thường
PASS dishes: q=_ là ký tự thường
{"ok":true,"data":[],"meta":{"total":0,…}}

Seed 1.500 món: q=% → đúng 2 món Combo 100% bò Úc, Bánh 50% đường; q=_ → Trà_sữa_nhà_làm.

Điểm mấu chốt về bằng chứng: kiểm tra thất bại được commit TRƯỚC bản sửa (407ae17), nên "trước khi sửa" là thật, không dựng lại sau. Chi tiết trong evidence/bug-like-wildcard.md.
Câu 4 · Lỗi phát hiện #2 (khi bấm thử giao diện)

Gần đúng: gõ bún ra 42 món, gõ bun ra 0 món

Nguyên nhân: pg_trgm coi ú khác u

Chuỗi được cắt thành nhóm 3 ký tự (trigram):

bun

Những gì nhóm biết nhưng chưa làm

Toàn văn chưa bỏ dấu

Cấu hình simple theo yêu cầu: "pho" không khớp "phở" ở chế độ Toàn văn. Hướng đi: cấu hình text search có unaccent như đã làm cho Gần đúng.

Fuzzy quét tuần tự

word_similarity(...) >= 0.3 trong WHERE không dùng được index trigram. 1.500 món vẫn nhanh; bảng lớn hơn nên dùng toán tử <% + index trên unaccent(name).

Offset với bảng rất lớn

OFFSET vẫn đọc qua các dòng bị bỏ. Hướng đi: keyset pagination (con trỏ id) cho Tải thêm / Cuộn vô hạn.

Trang không hợp lệ

Giữ hành vi Block 6: page=abc → trang 1, trang vượt → trang cuối. Slide 9–10 gợi ý items: [] / VALIDATION_FAILED — có thể đổi nếu cần.

Thể hiện nhóm hiểu giới hạn của lựa chọn hiện tại.

  • Bằng chứng trước khi sửa phải được ghi trước khi sửa.
