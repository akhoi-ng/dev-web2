1Bật 2FA · /account/security

  • QR vẽ ở server + secret key nhập tay vào app Authenticator
  • Nhập đúng một mã mới bật; 10 mã khôi phục hiện một lần, DB lưu HMAC
  • Bật, thay, tắt: tokenVersion + 1, nơi khác bị đăng xuất
  • Thay, tắt, tạo lại mã: nhập lại password + mã

2Quản trị chỉ dành cho Admin

  • Nút "Quản trị" chỉ hiện với Admin; role khác mở /admin/* thấy trang 403
  • API chặn thật: /api/admin/*, chefs, ingredients, ghi món → 403
  • Role đọc từ DB mỗi request: hạ quyền Admin là token đang dùng bị chặn ngay

3Dùng chung với bản SSR

  • Chung bảng users, mfa_challenges, recovery_codes và khóa MFA_ENC_KEY
  • Bật MFA ở bản nào thì cả hai bản đều hỏi mã; reset password không tắt MFA
  • Bỏ MFA_REQUIRED của Block 9; bản SSR giữ RBAC + ABAC cho Viewer, Editor

Lửa Hồng · Block 10 — MFA và phân quyền cho bản SPABáo cáo
Bản SSR đã có RBAC, ABAC và MFA từ Block 9 Bài 2; bản SPA khi đó chỉ chặn: tài khoản bật MFA nhận MFA_REQUIRED. Block 10 đưa MFA sang API và React SPA, và thu khu vực quản trị của bản SPA về chỉ Admin: giao diện ẩn lối vào và hiện trang 403, còn API trả 403 cho mọi endpoint quản trị với role khác (ẩn nút chỉ là giao diện, chặn thật nằm ở server). Viewer và Editor vẫn đăng nhập, xem thực đơn và bật 2FA ở /account/security. Handler ghi món vẫn giữ điều kiện ABAC như lớp kiểm tra thứ hai. Luồng đăng nhập theo slide "MFA khi client là SPA" của deck: API không có session nên trạng thái chờ MFA là một challenge ngắn hạn trả trong JSON, chỉ POST /api/auth/mfa nhận. Code mới: api/src/auth/mfa.js, api/src/routes/mfa.js, api/src/auth/policy.js, api/src/routes/dishes.js; SPA thêm /login/mfa và /account/security. Nghiệm thu sinh mã TOTP từ secret key đọc ở response thiết lập, như một ứng dụng Authenticator. Các dòng tiêu biểu: mã dùng lại bị từ chối, lần sai thứ 5 trả 401 MFA_TOO_MANY_ATTEMPTS, mã khôi phục dùng lần hai bị từ chối, reset password xong vẫn phải qua MFA; Viewer và Editor gọi 5 endpoint quản trị đều 403, sửa hay xóa món bị 403 và dữ liệu không đổi; hạ Admin xuống Editor trong DB thì token đang dùng bị 403 ngay.
